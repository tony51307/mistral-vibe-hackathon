# Pay-to-Think Dealer Economy Demo Plan

## Goal

Build a hackathon demo for the V1 Pay-to-Think dealer economy described in `economic_model.md`.

The demo should show autonomous agents managing three different economic forces:

- `X`: fixed entry fee, capital at risk, redistributed through the pot.
- `Y`: reasoning purchase, intelligence cost, permanently burned.
- `H`: dealer contribution, external value added to the pot.

The main claim remains:

> A perturbation-guided dynamic agent can buy expensive reasoning selectively, recovering some benefits of always thinking while spending less reasoning budget.

## V1 Constants

Use these defaults for the first implementation:

```yaml
players: 4
starting_bankroll: 80
entry_fee: 10
dealer_contribution: 12
season_rounds: 25
message_max_chars: 100
reasoning_prices:
  none: 1
  low: 2
  medium: 3
  high: 5
  xhigh: 9
rollover:
  enabled: true
  max_chain_for_demo: 3
show_hand:
  enabled: true
  trigger: "0 < bankroll < entry_fee"
  reasoning_tier: none
```

The `$` symbol means game currency, not real API dollars.

## Agents

Use four seats so the economy matches V1.

### 1. Fast Agent

- Always chooses `none` reasoning when it can play.
- Pays the fixed entry fee and the `$1` `none` tier.
- Uses a single cheap answer pass.
- Represents the no-thinking baseline.

### 2. Always Think Agent

- Always buys `xhigh` reasoning when it can afford it after entry.
- If it cannot afford `xhigh`, buys the highest affordable tier.
- Represents the high-cost accuracy baseline.

### 3. Dynamic Pay-to-Think Agent

- Uses the perturbation-guided strategy from `Pay-to-Think_ A Perturbation-Guided Reasoning Router.md`.
- Receives the mandatory dealer-funded router pass.
- Runs cheap perturbation probes during routing.
- Chooses one of `none`, `low`, `medium`, `high`, or `xhigh`.
- Uses deeper reasoning only when instability, problem value, or bankroll state justifies it.

### 4. Control Agent

For V1, add a fourth seat rather than changing the economy to three players.

Recommended first control policy:

- Buys `medium` reasoning whenever affordable.
- Falls back to the highest affordable lower tier if bankroll is constrained.
- Gives the demo a middle-spend baseline between Fast and Always Think.

Alternative later control policies:

- Random tier agent.
- Category-specialist agent.
- Previous-round adaptive heuristic agent.

## Round Protocol

### Phase 1: Category Reveal

The dealer reveals only the category.

Example:

```text
CATEGORY: PROBABILITY
```

The dealer does not reveal difficulty, expected accuracy, recommended reasoning tier, or the full problem yet.

Every active agent pays the fixed entry fee:

```text
X = $10
```

The dealer adds:

```text
H = $12
```

With four normal players and no rollover:

```text
pot = 4 * $10 + $12 = $52
```

### Phase 2: Table Talk

Each active agent may publish one public message of at most 100 characters.

Examples:

```text
Probability is usually good for me. I may spend.
Physics has been costly lately. Staying cautious.
Big pot means big reasoning.
```

Messages are visible to all agents before the problem is revealed. Agents cannot communicate again after the full problem appears.

For the first demo, table talk can be generated by a cheap model call or a deterministic policy. Store it in the round log either way.

### Phase 3: Problem Reveal

The dealer reveals the full short-answer problem.

Allowed categories:

- math
- physics
- computer science
- logic
- probability
- algorithms
- general quantitative reasoning

The dealer must not expose hidden difficulty metadata to agents.

### Phase 4: Mandatory Router Pass

Every active agent receives a lightweight dealer-funded routing step before buying reasoning.

The router may see:

- problem
- category
- current bankroll
- current pot
- round number
- public table-talk messages
- agent strategy memory
- opponent history
- available reasoning tiers

The router returns only:

```json
{
  "reasoning_tier": "medium"
}
```

The router should not solve the problem. Its cost is infrastructure cost and does not affect game bankroll.

### Phase 5: Reasoning Purchase

Each agent independently selects exactly one reasoning tier:

```text
none   $1
low    $2
medium $3
high   $5
xhigh  $9
```

The selected `Y` is deducted immediately and burned.

Agents may only buy tiers they can afford after paying entry.

Example:

```text
bankroll before round: $16
after entry: $6
available tiers: none, low, medium, high
unavailable tier: xhigh
```

There are no refunds, partial refunds, transfers, loans, negative balances, or extra reasoning purchases after this phase.

### Phase 6: Answer Submission

Each playing agent submits one short answer after its selected reasoning process finishes.

Agents cannot:

- communicate after problem reveal.
- change reasoning tier.
- revise an answer after submission.
- buy another reasoning tier.

The dealer checks correctness with deterministic answer keys whenever possible.

### Phase 7: Prize Distribution

Let `P` be the current total pot.

If one agent is correct:

```text
winner receives P
```

If `k` agents are correct:

```text
each winner receives P / k
```

All reasoning expenditures remain burned.

### Phase 8: No Correct Answer Rollover

If no agent answers correctly, the full pot rolls into the next round.

Example:

```text
round 7 pot: $52
number correct: 0
rollover out: $52

round 8 pot:
rollover in: $52
new entries: $40
dealer H: $12
total: $104
```

For demo stability, use a maximum rollover chain of 3. After that, the dealer may secretly draw the next problem from a more solvable pool. This should remain hidden from agents.

## Show Hand Rule

If an agent has:

```text
0 < bankroll < entry_fee
```

it cannot pay the normal entry fee. It may enter `SHOW_HAND` state.

Rules:

- The agent puts its entire remaining bankroll into the pot.
- The agent receives no paid reasoning.
- The agent answers with base/no-thinking behavior.
- Its bankroll becomes `$0` before the answer is judged.
- If wrong, it is eliminated.
- If correct, it receives its normal share of the pot and survives.

No emergency loans, discounted reasoning, or bankroll subsidies exist in V1.

## Dynamic Router Design

The dynamic agent uses the mandatory router pass to choose a tier, not to directly solve the problem.

Recommended router flow:

1. Inspect category, pot size, bankroll, public messages, and opponent history.
2. Run 3-5 cheap perturbation probes on the revealed problem.
3. Compare answer shape, confidence, and consistency across probes.
4. Estimate whether the problem is stable or fragile.
5. Select the cheapest reasoning tier that seems economically justified.

Suggested tier rule:

```text
if bankroll after entry cannot afford higher tiers:
  choose highest affordable tier only when pot is large; otherwise choose none/low

else if perturbation answers strongly agree and confidence is high:
  choose none or low

else if answers disagree and pot is normal:
  choose medium or high

else if answers disagree and pot includes rollover:
  choose high or xhigh

else:
  choose low or medium
```

Router output should include a private trace for the UI:

```json
{
  "reasoning_tier": "high",
  "stability": "low",
  "probe_answers": ["1/6", "5/33", "5/33", "1/6"],
  "economic_reason": "Low stability and rollover pot justify high reasoning."
}
```

Only `reasoning_tier` affects the game protocol. The rest is for demo explanation and logging.

## Reasoning-Tier Mapping

Keep the game protocol independent of exact Mistral API options.

Conceptual mapping:

```text
$1 none   -> single inexpensive response
$2 low    -> small reasoning budget
$3 medium -> moderate reasoning budget
$5 high   -> large reasoning budget
$9 xhigh  -> maximum reasoning budget and/or verification pass
```

If Mistral does not expose five distinct reasoning levels, preserve the five game tiers and map them internally to available mechanisms.

Possible implementation:

- `none`: cheap model, terse prompt, answer only.
- `low`: cheap model, short scratchpad instruction.
- `medium`: stronger model or larger max tokens.
- `high`: stronger model with structured reasoning prompt.
- `xhigh`: strongest prompt plus independent verification call.

Use environment variables:

```env
MISTRAL_API_KEY=...
MISTRAL_CHEAP_MODEL=...
MISTRAL_STRONG_MODEL=...
```

## Problem Bank

Start with a fixed dataset for reliable demos.

Problem fields:

```json
{
  "id": "probability_001",
  "category": "probability",
  "hidden_difficulty": "medium",
  "question": "A jar has 5 red balls, 4 blue balls, and 3 green balls. Two balls are drawn without replacement. What is the probability both are red?",
  "answer": "5/33",
  "accepted_answers": ["5/33", "20/132"],
  "explanation": "P(red then red) = 5/12 * 4/11 = 20/132 = 5/33."
}
```

Important:

- `hidden_difficulty` is available only to the dealer and metrics.
- Agents never receive `hidden_difficulty`.
- Questions should have short, objectively judgeable answers.
- Prefer deterministic answer validation over model-judged validation.

Initial hidden difficulty distribution:

- trivial/easy: 30%
- medium: 30%
- hard: 25%
- very hard: 15%

Initial category distribution:

- math: 20%
- physics: 20%
- computer science: 20%
- logic: 15%
- probability: 15%
- algorithms/reasoning: 10%

For experiments, use seeded problem sequences so different agent policies can be compared on identical seasons.

Track per agent:

- Starting bankroll.
- Current bankroll.
- Rounds entered.
- Show Hand attempts.
- Correct answers.
- Incorrect answers.
- Reasoning dollars burned.
- Entry dollars paid.
- Prize dollars won.
- Net profit.
- Accuracy.
- Reward per reasoning dollar.
- Tier distribution.

Track economy health:

- Total money supply: `sum(agent bankrolls) + unresolved jackpot`.
- Average reasoning spend per active agent per round.
- Reasoning-tier distribution.
- Jackpot frequency.
- Show Hand timing.
- Accuracy by category.
- Accuracy by hidden difficulty.
- Accuracy by reasoning tier.
- Reward per game dollar spent on reasoning.

Initial healthy target:

```text
average Y per active agent per round: $2.5-$3.2
none: 25-35%
low: 20-30%
medium: 20-30%
high: 10-20%
xhigh: 2-8%
```

These are diagnostics, not enforced rules.

## Recommended First Build

Build a 25-round Streamlit season using fixed problems, abstract game dollars, and deterministic validation.

For a shorter live pitch, include a "Run 5 demo rounds" mode that uses the same V1 rules but stops early.

The first successful demo should show:

- Entry fee `X` redistributes capital through the pot.
- Reasoning cost `Y` burns capital.
- Dealer contribution `H` creates new value.
- No difficulty signal is revealed to agents.
- Jackpot rollover makes some rounds economically worth more reasoning.
- Poor agents lose access to expensive intelligence.
- Dynamic routing spends more when answers are unstable or stakes are high.

## V1 Non-Features

Do not add these to the first demo:

- Variable entry bids.
- Difficulty-dependent dealer contribution.
- Agent-to-agent transfers.
- Loans.
- Negative bankrolls.
- Wealth-dependent reasoning discounts.
- Confidence wagers.
- Speed bonuses.
- Partial refunds for reasoning.
- Dealer hints about difficulty.

These should stay out of V1 so the demo isolates the Pay-to-Think behavior.
